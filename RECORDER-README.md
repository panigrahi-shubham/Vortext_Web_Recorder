# TPHub Web Recorder

A Playwright recorder that writes the test you would write by hand: **Page Object classes plus a
spec**, **ranked and verified locators**, **pre/post assertions suggested from what changed on the
page**, and **real waits** instead of `waitForTimeout`.

You use the website normally in a headed browser. A toolbar inside the page and a side panel show
every step, the locator chosen for it (with a score), suggested checks, and the generated code live.

---

## 1. Quick start (Windows PowerShell, 10 minutes)

Requirements: Node.js 20 or newer (tested with 22, built for 24) and PowerShell.

```powershell
# 1. Unzip, then open PowerShell in the project folder (quotes matter if the path has spaces)
cd "C:\Tools\tphub-web-recorder"

# 2. Install the three dependencies and the Chromium browser
npm install
npx playwright install chromium

# 3. Try it on the bundled demo shop (no internet needed)
npm run demo
```

`npm run demo` opens two windows: the demo shop with the TPHub toolbar at the bottom, and the side
panel. Then:

1. Type `standard_user` / `secret_sauce` and click **Login**.
2. Click **Add to cart** on *Trail Backpack*. The panel suggests `cartBadge` should show `1` (ticked).
3. Click the cart icon. In the toolbar choose **Assert**, click a table row, pick **count equals**.
4. Click **Save files** in the panel (or press Ctrl+C in PowerShell: it saves and quits).
   The demo writes to `.\demo-tests\tests` and creates `.\demo-tests\playwright.config.ts`.
5. Run the generated test against the demo site:

```powershell
npm run fixture-site          # window 1: keeps the demo shop running on http://127.0.0.1:4900
```

```powershell
$env:TEST_PASSWORD = 'secret_sauce'      # window 2
npx playwright test -c demo-tests
```

### Recording your own application

```powershell
npx tsx src/cli.ts record --url https://your-app.example.com --out .\tests --name "user updates profile"
# or the same through npm (note the extra --):
npm run record -- --url https://your-app.example.com --out .\tests
```

Log in once and keep the session for later recordings and tests:

```powershell
npm run record -- --url https://your-app.example.com/login --out .\tests --save-state .\auth.json
npm run record -- --url https://your-app.example.com/dashboard --out .\tests --storage-state .\auth.json
```

When you start logged in, the spec gets `test.use({ storageState: 'auth.json' })` automatically.

## 2. What it generates

```
tests/
  specs/<flow-name>.spec.ts            the test: one call per user intention + assertions
  pages/<PageName>.ts                  one class per page (route) with locators and methods
  fixtures/<flow-name>.data.json       values you typed (passwords masked)
  utils/smart.ts                       only if you used coordinate fallbacks
  assets/                              upload placeholders and debug snapshots
  recordings/<flow-name>.recording.json  the raw steps (no secrets) to regenerate code later
  tsconfig.json                        only if none exists above the output folder
```

Example (from `examples/demo-shop`, generated by this tool and verified to pass):

```ts
await test.step('Add to cart (Trail Backpack)', async () => {
  // 5. Click button "Add to cart" in "Trail Backpack"
  await expect(inventory.addToCartButton('Trail Backpack')).toBeVisible(); // pre-assertion
  await inventory.addToCart('Trail Backpack');
  await expect(inventory.cartBadge).toHaveText('1'); // suggested: cart-badge '1' appeared
});
```

```ts
/** button "Add to cart" inside the item that contains `itemName` */
addToCartButton(itemName: string): Locator {
  return this.page
    .getByRole('listitem')
    .filter({ hasText: itemName })
    .getByRole('button', { name: 'Add to cart' });
}
```

### How the main ideas work

| Idea | What the recorder does |
|---|---|
| **Locator ranking** | Builds every candidate (test id 100, role+name 90, label/placeholder 85, text 75, scoped row 60, CSS 45, `.nth()` 40, coordinates 10), then **checks each one in the live page**: it must match exactly one element and it must be the element you clicked. Dynamic text (counts, prices, dates, order numbers) is penalised and replaced by a regex of its steady part, e.g. `/^Add to cart/`. |
| **Replay-verified steps** | Your click is intercepted, the locator is chosen, and the click is **performed through that locator**. If the locator could not click it, you see a warning at once, not in CI next week. |
| **Repeated rows and cards** | Finds the repeated container (table row, list item, card, web component) and a unique text inside it: `getByRole('row').filter({ hasText: 'Bob Singh' }).getByRole('button', { name: 'Edit' })`. In Page Objects the row text becomes a method parameter. |
| **Settle detection** | After each action it waits until there were no DOM changes and no fetch/XHR for 300 ms (8 s max, long-polling ignored) and shows how long it took. |
| **Suggested checks** | Compares the page before and after: URL, title, new heading, dialog, toast, alert, checkbox/tab/accordion state, changed text, list length, disappeared spinner/modal. The best one is ticked; you can tick others in the panel. |
| **Pre-assertions** | `toBeVisible()` before clicks, plus `toBeEnabled()` before fills; skipped when the previous check already proved it. |
| **Secrets** | Password/token/OTP fields are masked in the JSON and read from an environment variable: `process.env.TEST_PASSWORD ?? data.password`. |

## 3. Toolbar modes (bottom of the page)

| Mode | Click on an element… |
|---|---|
| **Record** | performs and records it (typing is recorded as the final value per field) |
| **Assert** | opens a menu of checks: visible, hidden, enabled, disabled, editable, checked, focused, text equals/contains (dynamic parts pre-removed), value, attribute, count of similar items, URL, title, screenshot (`--screenshots`), accessibility (if `@axe-core/playwright` is installed) |
| **Wait for** | records "wait until visible / hidden" as a web-first assertion |
| **Inspect** | shows every candidate locator with its score; nothing is recorded |
| **Hover / Scroll / Drag** | records `hover()`, `scrollIntoViewIfNeeded()`, or `dragTo()` (click source, then target) |
| **Pause** | stops recording so you can set up the page |

Hovering anything shows the chosen locator and a coloured score (green ≥ 75, amber ≥ 45, red below).
The click-style selector sets how new clicks are written: **Locator**, **Locator + point**
(`clickOrAt`: tries the locator for 3 s, then clicks the recorded point), or **Point only**.

## 4. Side panel

Left: step cards with score badge, warnings, pre-assertion toggle, click style, **alternative locator
picker**, suggested checks, dialog accept/dismiss, a note field (becomes a code comment), delete, and
drag-to-reorder. Right: live code for every file, Copy, Save, test name, POM or flat style.

## 5. All commands

```powershell
npx tsx src/cli.ts record   --url <url> --out <dir> [options]
npx tsx src/cli.ts demo                                   # demo shop + recorder
npx tsx src/cli.ts check    <page.html|url> [--selector "css"] [--json]
npx tsx src/cli.ts generate --from <file.recording.json> [--style flat] [--name "..."] [--out dir]
npx tsx src/cli.ts audit    .\tests                       # find fixed waits, XPath, nth(), $ ... in existing tests
npx tsx src/cli.ts serve-fixtures [--port 4900]           # the demo site only
```

`record` options: `--name`, `--viewport 1280x720`, `--browser chromium|firefox|webkit`,
`--storage-state`, `--save-state`, `--base-url`, `--panel-port 4800`, `--test-id-attr data-test`
(otherwise read from `playwright.config.ts`), `--allow-css`, `--style pom|flat`, `--keep-secrets`,
`--overwrite`, `--coords-ratio`, `--screenshots`, `--no-panel-open`.

**Saving never silently overwrites your edits.** If a file exists and differs, the new version is
written next to it as `Name.generated.ts` with a +/- line summary, unless you pass `--overwrite`.

### `check`: why did it pick this locator?

```powershell
npx tsx src/cli.ts check .\fixtures\snapshots\users-table.html
npx tsx src/cli.ts check https://your-app.example.com/login --selector "form button"
```

Prints, for every interactive element, the chosen locator, its score, warnings and the runners-up
(with the reason they lost: "matches 3 elements", "matches a different element"...). Files saved by
PowerShell as UTF-16 are decoded correctly. The **Debug snapshot** button saves the DOM, a full-page
screenshot, the snapshot JSON and the ranking of every step to `<out>/assets/debug-<time>/`.

## 6. Troubleshooting

| Problem | What to do |
|---|---|
| `Port 4800 is already in use` | Another recorder is running. Close it or add `--panel-port 4801`. |
| `browserType.launch: Executable doesn't exist` | Run `npx playwright install chromium` (or `firefox` / `webkit` for `--browser`). |
| `npm run record --url ...` ignores the URL | npm needs `--` before your options: `npm run record -- --url ...` |
| Paths with spaces | Quote them: `--out "C:\My Tests\e2e"`. |
| Generated test fails at the password | Set the variable first: `$env:TEST_PASSWORD = '...'` (name is shown at the top of the spec). |
| A step shows *"replaying through the locator failed"* | The page covered or moved the element. Try again after it settles, pick an alternative locator in the panel, or switch that step to *Locator + point*. |
| A step shows *"page did not settle within 8 s"* | The page polls or animates forever. The step is still recorded; the next assertion does the waiting. |
| Score is red / `.nth()` warning | No unique semantic locator exists. Ask developers for a `data-testid`, or use `--test-id-attr` if they use another attribute. |
| Clicks are not recorded | You are in another mode (look at the toolbar) or **Pause** is on. |
| Typed text missing | Text is recorded when you leave the field, press Enter, or click elsewhere. |
| Saved `.generated.ts` files | Your file was edited by hand; compare and merge, or re-save with `--overwrite`. |
| `tsc` cannot import the data JSON | Enable `"resolveJsonModule": true` and `"esModuleInterop": true` in your tsconfig. Playwright itself runs it without changes. |

## 7. Limits (honest list)

- Chromium is the tested browser. Firefox and WebKit use the same APIs but were not run here.
- Closed shadow roots cannot be recorded (no script can see inside them). Open shadow DOM works.
- Cross-origin iframes work for recording; their element-level suggestions need the frame to load
  the recorder script, which Playwright does for every frame.
- Typing is recorded as `fill()` (final value). Key-by-key behaviour (autocomplete that needs real
  key events) needs a manual change to `pressSequentially()`.
- Canvas apps and drag gestures that are not HTML5/pointer based fall back to coordinates.
- Suggested checks come from heuristics: review them; untick anything that is not part of the test.
- Page grouping uses the URL route; a single-URL wizard becomes one Page Object.

## 8. Development

```powershell
npm test                 # all unit + integration tests (records flows and runs the generated specs)
npm run test:unit
npm run typecheck
npx tsx scripts/make-example.ts   # regenerate examples/demo-shop
```

Layout: `src/locators` (candidates, pure ranking, live verification), `src/recorder` (session, settle,
snapshots, in-page scripts `page-core.js`/`page-ui.js`), `src/suggest` (pure diff → checks),
`src/codegen` (model, page objects, spec, formatter, saving), `src/server` (panel), `fixtures/site`
(demo shop and special-case pages), `test/` (unit and integration tests).

No telemetry, no network calls except to the site you record. The panel binds to 127.0.0.1 only.
